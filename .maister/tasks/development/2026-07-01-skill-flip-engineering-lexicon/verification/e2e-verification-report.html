Discrepancies

Minor Category chip counts don't recompute against active search/level filters

FieldDetail
Spec requirementMockup annotation on screen:browse-filter-grid: "Live count per category recomputed on every filter change"
ExpectedChip counts (e.g. "Java (20)") narrow to reflect the active search text / level selection
ActualFilterBar.ts's categoryCounts() always counts against the full, unfiltered dataset passed at construction time
EvidenceSearching "deadlock" narrowed the grid to 1 result, but the "Java" chip still read "(20)"
Root cause hypothesisCount calculation reads the constructor-time entries prop instead of the live filtered state
User impactLow — filtering/search/result-count remain accurate; only the chip numbers look stale
Recommended fixRecompute categoryCounts() against entries filtered by search+level (excluding the category facet itself) on every onChange
WorkaroundNone needed — result-count line remains the accurate source of truth
