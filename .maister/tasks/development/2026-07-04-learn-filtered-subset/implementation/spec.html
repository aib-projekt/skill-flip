TL;DR

Learn Mode will draw only from Browse's active category/level filter, persisted in localStorage (search text excluded). AppShell becomes the sole owner/mediator of BrowseFilterState; BrowseGrid/FilterBar gain hydration + upward propagation; LearnMode gains updateFilter(), a dismissible topbar filter chip, and empty-subset handling via a newly-extracted shared EmptyState component. Purely additive across 5 modified files + 1 new file, zero breaking signatures. A fully-approved product-design feature-spec is the authoritative source for every type shape, storage key, and wiring detail.

Key Decisions

  • Persisted schema is exactly { selectedCategories: Category[], selectedLevel: Level | 'All' } under key skillflip:browse-filter-state — searchQuery is structurally absent from the type. (overrides an earlier generic-convention inference)
  • AppShell is the sole owner/mediator of filter state — BrowseGrid and LearnMode stay mutually decoupled.
  • EmptyState is extracted from BrowseGrid.renderEmptyState() into a shared, parameterized component — zero visual/behavioral change for Browse.
  • Progress persistence is unaffected; only the stats display becomes subset-scoped via existing, signature-unchanged functions.
  • LearnMode.ts's entries binding (currently const) must become mutable to support updateFilter().

Open Questions / Risks

  • infoFilterBar.ts gains initialState with no dedicated test file — accepted, spec-confirmed gap (covered via BrowseGrid.test.ts integration).
  • infoLearn Mode's empty-subset path is new interaction surface with no direct precedent in LearnMode.ts itself — sequence it last in implementation.

Goal

Learn Mode's card pool automatically reflects whatever category/level filter is active in Browse, and that filter persists across page reloads (search text is session-only), so a user can focus a study session on one topic without re-filtering every visit.

User Stories

As a returning user, I want the category/level filter I set in Browse to still be active next time I open the app, so I don't have to re-select it every session.
As a user studying a specific topic, I want Learn Mode to only show cards from my active Browse filter, so my study session stays focused without an extra "start filtered session" step.
As a user in Learn Mode, I want to see which filter is currently active (and clear it in place) without switching back to Browse, so I can course-correct without losing my spot.
As a user whose filter matches nothing, I want a clear, actionable message in Learn Mode instead of a blank or broken screen, so I know exactly what to do next.

Core Requirements

#Requirement
1Persist category/level filter across sessions via new storage.ts functions (readFilterState/writeFilterState), key skillflip:browse-filter-state. searchQuery never written/read back.
2AppShell owns and mediates filter state: hydrates on construction, defines handleFilterChange(newState) (updates state, writes storage, calls learnMode.updateFilter()).
3Filter changes propagate upward: FilterBar.initialState (hydration only) → BrowseGrid.initialFilterState/onFilterChange → bubbles to AppShell.
4LearnMode gains updateFilter(newEntries) — replaces internal entries, immediately redraws a new card from the updated subset.
5Dismissible .filter-chip in Learn Mode's topbar, visible only when filter is non-default; label format matches FilterBar's existing "+N more" convention; clears via the same handleFilterChange path.
6Empty-subset handling: updateFilter([]) renders shared EmptyState instead of Card; never falls back to a wider pool; mark controls hidden.
7Shared EmptyState component extracted verbatim from BrowseGrid.renderEmptyState(); Browse refactored to use it with zero behavior change.
8Progress stats (mastered/shaky/new) scope to the active filtered subset in both views; underlying progress persistence (keyed by entry id) unaffected.
9resetProgress() scope unaffected — still clears all entries globally, not just the filtered subset.

Technical Approach

Data flow: main.ts fetches glossary → AppShell hydrates filterState from readFilterState() (merged with fresh searchQuery: '') → passes state down to BrowseGrid/FilterBar and an already-filtered subset to LearnMode → on every FilterBar change, BrowseGrid bubbles onFilterChange to AppShell → handleFilterChange() updates state, writes storage (2-field subset only), calls learnMode.updateFilter() → LearnMode redraws card + chip + stats atomically.

Implementation sequencing (lowest-risk first)
  1. Extract EmptyState.ts — self-contained, independently testable.
  2. Add storage.ts functions — mirrors existing pattern.
  3. Wire AppShell as mediator.
  4. Thread FilterBar/BrowseGrid hydration + upward propagation.
  5. LearnMode.updateFilter(), filter chip, empty-state, subset-scoped stats — most new surface area, built last.
Implementation note: LearnMode.ts line 45 currently does const { entries } = options. Supporting updateFilter(newEntries) requires converting this to a mutable local and updating every downstream read (initial draw, advanceToNextCard(), stats, chip). Mechanical consequence of the feature, not a design choice — flagged for explicit planner scoping.

No changes required to main.ts, Card.ts, learnAlgorithm.ts, filters.ts's signatures, or computeBucketCounts/renderProgressStats shapes. No new runtime dependencies.

Success Criteria

  • Filtering to a subset in Browse and switching to Learn Mode shows only cards from that subset.
  • Reloading preserves category/level filter; search text does not carry over.
  • A zero-match filter produces a clear, actionable empty state — never a blank screen or silent fallback.
  • Existing bucket-weighted progress tracking is unaffected across filter changes.
  • All 31 existing tests pass with zero regressions, plus all new test cases; npm test is the acceptance gate.
  • E2E scope: filter in Browse → switch to Learn Mode → see chip → clear it → trigger empty state → reload → confirm persistence.
